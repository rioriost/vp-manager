# 解像度指定・PPTX埋め込み動画の実装レビュー

2026-10-03、0.2.0の追加範囲を確認した。独立テスト34件は成功し、確認した範囲に未修正の阻害事項はない。対象は、1スライドに1本の動画を置き、ノートで前後と途中の説明時刻を指定する初期実装である。試験には合成した動画・音声と一時PPTXを使い、実VOICEPEAK、利用者の原稿、辞書設定には触れていない。

公開版の番号は同日に0.1.1へ訂正した。本レビューで確認した音声・動画処理は0.2.0と同一で、既存のジョブ形式も変更していない。

## 原稿と時刻を保ち、収まらない説明は停止する

制御記号は独立した行に置く。PowerPointの段落内改行も同じ行境界として扱い、元の文字列、位置、段落の対応を保存する。`【再生前】`の音声が終わってから動画を開始し、`【0:30付近】`などの時刻は元動画の先頭から数える。`【再生後】`では最終フレームを保持する。制御行は合成、読み候補、読み補正の対象から除外される。

時間計画には生成済みWAVの実長を使う。説明が次の指定時刻に重なる、指定時刻が動画を外れる、説明が再生終了を越える場合は、必要時間と不足時間を示して停止する。原稿を切ったり、動画を加減速したりして予定へ押し込まない。動画の位置、ノートの時刻、原文を保存済みジョブで変更しても、原本PPTXとの再照合で停止する。

1080pは1920×1080の出力枠であり、縦横比の異なるスライドは比率を保って収める。動画はPPTXの矩形位置に重ねる。動画自体の縦横比と配置枠が異なる場合は、別の見た目へ変換せず、対応範囲外として停止する。

## 実MP4で減衰、復帰、フレーム境界を検査した

独立テストは `tests/test_timed_video_review.py` に置いた。FFmpegで2秒の赤から青へ変わる動画を作り、元音声に440 Hz、説明音声に880 Hzを使った。MP4を再デコードし、指定時刻の画像と音声の周波数成分を検査した。試験結果は次のとおり。

| 検査 | 結果 |
|---|---|
| 前・途中・後の説明を含む単一スライド | 320×180、10fps、30フレーム、映像・音声とも3秒 |
| 動画内1秒の説明 | 動画開始から1秒後、出力全体では1.5秒から0.3秒間に配置 |
| 元音声の減衰 | -12 dB指定に対し、減衰中の振幅比を約0.251として検出。説明後は元の振幅へ復帰 |
| 説明の音量 | ミックス前後で約0.2の振幅を維持。この例の追加ゲインは1 |
| 過大なミックス | 入力のピーク1.8に対し、記録されたゲイン0.98/1.8を適用し、出力ピーク0.98 |
| 通常スライド→動画→非表示スライド | 10fpsと29fpsの両方で順序、説明の位置、非表示スライドの包含・除外が一致 |
| 結合後の長さ | 10fpsで32/34フレーム、29fpsで94/100フレーム。A/V差は1サンプル以内 |
| 動画のみ・音声なし | 空ノートと再生指示だけの両方で再生し、無音の音声トラックを出力 |
| 元ファイルの保全 | PPTX、各説明WAV、既存の全体・スライド別WAVのハッシュが不変 |

単一スライドの出力から、再生前、動画後半、再生後の画像を抽出して目視した。赤から青へ変わり、動画終了後も青の最終フレームを保持する。矩形の位置と大きさ、外側の緑背景も維持されていた。これは合成試験の目視結果であり、PowerPointアプリでの原稿照合とは区別する。

元音声の減衰には、連続する説明区間の内側で最大50 msの音量変化を付け、区間外では元のゲインへ戻す。クリッピング回避のため全体ゲインを下げた場合は、その値と適用前後のピークを記録する。設計時には[FFmpegのamixの既定正規化](https://ffmpeg.org/ffmpeg-filters.html#amix)を確認した。実装はサンプル配列を明示的にミックスしており、既定の自動正規化に音量を委ねていない。

## レビューで見つけた欠落と時間のずれは修正済み

初版では、短い通常スライドの後に動画を結合すると、フレーム数は32でも映像時間が3秒、音声時間が3.2秒になる場合があった。全セグメントのB-frame設定をそろえて解消し、完成MP4の時間検査は緩めていない。また、29fpsの丸め済みサンプル位置を切り上げ直すことで余分な1フレームが加わる問題を、フレームとサンプルの境界計算で修正した。

混在スライドの出力が既存の全体WAVを通常スライド部分だけで上書きする問題も修正された。混在出力の通常スライド音声はメモリ上で組み立て、既存WAVを更新しない。全画面の矩形幅が浮動小数点の誤差で1918 pxになる問題は、整数比による計算へ変更している。

入力側では、制御行が読み候補に混ざる経路、読み補正後に制御行を音声へ戻す経路、旧形式の参照を持たない外部動画の見落とし、動画の可視枠線の見落としを修正した。[OOXMLのMedia定義](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.office2010.powerpoint.media?view=openxml-3.0.1)に従い、外部リンクと埋め込み参照が共存する場合もリンクを無視しない。測定済みの時間計画、音声ハッシュ、配置、解像度、減衰量と余白設定は、出力の来歴情報へ含めた。

## 矩形動画への対応と、日本語の聴取評価は分ける

複数動画、外部参照、回転・反転、切り抜き、PowerPoint側の再生範囲変更、装飾、前面図形との重なりなどは対応範囲外として停止する。画面切替、一般のアニメーション、クリック操作、独立した音声オブジェクトは再現しない。背景PDFの内容そのものが元スライドと一致するかは、生成後の目視確認が必要である。

このレビューは短い合成クリップでの配置、同期、音量、原本保全を対象とした。長時間・大容量の動画、多様な実コーデック、実際の日本語ナレーションの自然さは網羅していない。合成音声のQAは試験用の固定情報であり、人による聴取承認を代替しない。出力は引き続き `draft` とし、利用者の実原稿では再生開始、各説明の時刻、音量の復帰、スライド境界を映像と聴取で確認する。

再実行は `.venv/bin/python -m pytest -q tests/test_timed_video_review.py`。最終独立実行は34件成功、5.52秒。対象テストのRuff検査も成功した。
