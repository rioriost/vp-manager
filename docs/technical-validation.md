**VOICEPEAK 1.2.23では、辞書反映・単語アクセント・短文合成をCLIで扱える**

実施日：2026-10-03 / macOS / 話者：Japanese Female 1。対象はローカルのVOICEPEAK 1.2.23です。合成とASRはローカルで実行しました。最終的な自然さの聴取評価と、実際のPPTXから動画までの通し検証は今回の範囲に含まれません。

アクティベート後の正式な検証記録は30コマンド、音声出力23件です。このうち反復文字による文字数境界試験3件を除く20音声を、期待原稿を渡さずWhisperで文字起こししました。前提確認時のタイムアウトは別記録です。

**辞書変更は音声で確認し、検証後に原状へ戻した**

架空語は、未登録の状態では英字列として文字起こしされました。JSONへ読み「サクラモチ」を登録すると「桜餅を確認します」、読みだけを「タケノコ」に変更すると「タケノコを確認します」になりました。登録を除いた対照音声は、最初の未登録音声とSHA-256まで一致しています。

検証で使った品詞値は`Japanese_Koyuumeishi_ippan`と`Japanese_Futsuu_meishi`です。両方とも指定した読みを生成しましたが、単一の例で品詞選択の文脈的な正しさまで確認したわけではありません。

アクセント0・1の音声は、それぞれASRで「飴が好きです」「雨が好きです」となりました。近似音高も語頭から異なります。ただし、ASRの漢字選択や波形差は自然さの保証ではありません。今回確認したのはアクセント指定が合成結果に作用することです。

一時変更の直前に`dic.json`・`user.dic`・`user.csv`を私用の一時ディレクトリへ退避し、終了後にバイト列と時刻を復元しました。3ファイルとも検証直前のSHA-256と一致しています。`dic.json`は564件のままで、検証用単語は残っていません。更新版の通常起動で派生辞書が再生成されるため、復元基準は1.2.23のアクティベート・通常合成後の状態です。

**失敗を観測した入力は、事前検証と読み補正で扱う**

記号を含む登録済み用語の入力で異常終了を1件観測しました。対応するカタカナ表記では音声が生成され、ASRでも意図した読みになっています。原因の特定や一般化はしていません。既知の不安定な入力を自動で繰り返さず、原文を保持したまま読み上げ用の表記へ変換する方針にします。

存在しない話者を指定した場合も正常な入力エラーとしては終了しませんでした。本体は話者一覧にない値をVoicepeakへ渡さない設計にします。23件の出力すべてについて、生成の成否と音声形式を記録しています。ログに多数の`iconv_open is not supported`が出る場合にも音声生成は成功しており、この文言だけを失敗判定に使えません。

異常終了の原因調査や再試行は今回行っていません。現在の検証スクリプトからは、すでに不安定と分かった入力の再実行を除いています。初回記録と現行スクリプトの試験件数はその分だけ異なります。

**確認できていない機能は、初期版の前提から外す**

- 任意のイントネーション曲線、モーラごとの長さ、SSML、`.vpp`をCLIから直接制御する公開オプションは、1.2.23のヘルプにありません。隠れた機能の存在を否定するものではありません。
- GUIのSSMLインポートと、その後の出力を自動化する経路は未検証です。
- GUIと辞書更新の同時実行、多重CLI実行、他の話者、長時間の連続制作は未検証です。
- 辞書のアクセント値から自然さを自動判定する仕組みは未実装です。
- PowerPointでの描画、アニメーション、フォント、ノート抽出、非表示スライド、実PPTXからMP4までの通し検証は実装計画の受入試験に残しています。
