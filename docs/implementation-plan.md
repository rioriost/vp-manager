**Python本体に制作状態と検証を持たせ、Skillが読みと修正方針を判断する**

2026-10-03 / レビュー反映版。当初の実装計画を残しています。同日にPython本体とSkillを実装し、辞書の確定保存と受入音声の参照も追加しました。実装済み範囲は[初期検証](implementation-validation.md)と[継続検証](continuation-validation.md)を参照してください。本文の`persist_verified`方針は`promote-dictionary`コマンドとして実装しています。自然さの一般化判定など、計画段階の項目も含まれます。

初期版の到達点は、テキスト・UTF-8テキストファイル・ノート付きPPTXから、読みを調整したWAVと静止スライドのMP4を作ることです。CLIで扱える単語アクセント、速度、全体ピッチ、休止時間を使います。任意のイントネーション曲線、アニメーションの再現、MCP、AI APIを組み込んだ無人常駐運転は、基礎経路の完成後に扱います。

**1. Pythonが工程を管理し、AIの判断は構造化データで受け取る**

```mermaid
flowchart LR
    U[利用者の依頼] --> S[Skillとホスト側AI]
    S -->|CLI操作とJSONの判断結果| C[Python CLI]
    C --> J[原稿・辞書・工程の状態]
    J --> V[VOICEPEAKアダプター]
    V --> Q[ローカルASRと音響検査]
    Q -->|修正候補と証拠| S
    Q --> A[音声結合・映像合成]
    A --> O[WAV・MP4・検証記録]
```

Python側がファイル処理、辞書の書き込み、文字数検査、合成、音声検査、再開、動画出力を担当します。AIは用語の読み・品詞・アクセント候補、意味を保つ区切り、検査結果からの修正候補をJSONで返します。AIから受け取るのはデータであり、実行するPythonコードやシェルコマンドにはしません。

初期版では独立したAI APIキーを必要としません。利用中のCodexなどのホスト側AIがSkillに沿って判断します。ホストが中断したら`needs_decision`で保存し、再開後に続けます。音声生成を開始しただけで、チャットを閉じた後もAIによる修正が続くとは約束しません。

Skillはワークフローと判断基準を記述し、決定的な処理をPythonへ任せる方針です。[OpenAI公式のSkill構成](https://learn.chatgpt.com/docs/build-skills)に合わせ、説明と実処理を重複させません。

**2. 制作単位はスライド・段落・短い音声区間を保持する**

入力を読み込むと、原文のコピー、ファイルのハッシュ、スライド順、PPTX内部の識別子、段落、非表示状態を記録します。ノートでは本文のプレースホルダーだけを抽出し、スライド番号・ヘッダー・フッターを読みません。XMLのファイル名の番号を表示順とみなさず、リレーションを解決します。

原文と読み上げ用原稿を別に持たせます。補正は原文の位置と一致する範囲に紐づけ、数値・単位・否定・製品名を勝手に言い換えないようにします。既定の修正範囲は読み・アクセント・句読点・区切りです。内容を変える書き換えは別の依頼として扱います。

読み補正を適用した後で、段落→文→文節相当の順に140コードポイント以内へ分割します。単語、数値と単位、括弧の途中をできるだけ避けます。1語自体が長過ぎる場合は切り捨てず`needs_decision`にします。正規化は比較用と出力用を区別し、数式や識別子を壊す一律の記号削除はしません。

非表示スライドも必ず一覧に含めます。音声生成は全スライドを選べるようにし、動画は既定で表示スライドだけを収録します。ノートが空のスライドは黙って省かず、無音表示時間と警告を記録します。アニメーションや埋め込み動画を検出した場合は、静止画では保持できないことを出力計画に示します。

**3. 用語候補と確定辞書を分け、検証を通った語を追加する**

候補検出は英字列、略語、記号を含む語、数字と単位、既存の補正履歴を起点にします。日本語の未知語検出を広げる際は形態素解析を追加しますが、解析器の未知語判定をVoicepeak内部辞書の登録有無と同一視しません。ユーザー辞書にないだけで誤読すると決めつけず、既存の読み上げ結果も材料にします。

AIの候補には表記、読み、品詞、アクセント候補、対象文、適用範囲、根拠を含めます。モデル自身の確信度だけで採用せず、型、読みの文字種、モーラ数、品詞の許可値、対象範囲、試験音声で検査します。最初に書き込む品詞は、実測した普通名詞と固有名詞一般に限定します。他の品詞が必要な語は保留し、対応試験を追加します。

辞書登録と原稿内の読み補正は併用します。記号付き語などは原文全体を読みへ置換し、必要なら置換後の読み用表記にもアクセントを適用します。既存辞書との衝突や、文脈によって読みが変わる語は、原稿内の補正を優先します。

書き込みは候補集合ごとにまとめます。GUIが閉じていること、同じ本体の別ジョブが書き込んでいないこと、退避後に外部変更がないことを確認し、バックアップと差分を保存してから原子的に置換します。`user.dic`と`user.csv`はVoicepeakが再生成します。GUIは本体のロックに従わないため、書き込み前後のハッシュ確認も必要です。

一時辞書で生成・比較した後、検証済みの新規語を共通辞書へ保存する`persist_verified`を標準方針とします。既存語の上書きは自動で行いません。保存しない`temporary`も用意します。候補・根拠・採用状況は本体の管理データに保存し、Voicepeakの辞書JSONへ独自フィールドを追加しません。

中断時には復元が必要かを示す記録を先に保存します。外部変更があれば機械的に古い辞書を戻さず、両方を保存して`needs_recovery`にします。GUIの強制終了、ライセンス情報の操作、実行ユーザーを変えての制約回避は実装しません。

**4. 出力の存在、内容、読み方を別々に検査する**

| 検査層 | 初期版の内容 | 判断の限界 |
|---|---|---|
| ファイル・音響 | WAVの実在、読込可否、サンプルレート、チャンネル、有限値、非無音、クリッピング、先頭末尾の切れ、音量 | ファイルが正常でも発音が正しいとは限らない |
| 内容 | ローカルWhisperの期待原稿なしASR、読み落とし・重複・重要語・数値・単位の照合 | 表記揺れとASR誤認がある。CERだけで合否を決めない |
| 読み・韻律 | 辞書の読み候補、発話の長さ、休止、速度、アクセント候補の比較、既知の受入音声との差 | ASRや音高差だけでは自然さを保証できない |
| 動画 | 対象スライド数、順番、映像・音声ストリーム、総時間、境界同期、先頭末尾と代表フレーム | PowerPointの描画と静止画化の妥当性は別に確認する |

検査結果は`pass`・`fail`・`uncertain`で保存します。内容の不確実さが残る成果物は`draft`として出力し、最終合格にしません。発音・自然さの自動採用基準は、利用者が受け入れた音声と、誤読を含む評価セットから決めます。数値未調整のAI採点をそのまま合格基準にしません。

修正は問題区間と接続する境界だけを対象にします。1区間あたり初回＋修正3候補を上限にし、ジョブ全体の生成数・時間にも上限を置きます。改善がなければ打ち切り、最良の候補と未解決理由を残します。異常終了や入力不備は同じ入力で反復せず、環境確認または読み補正へ戻します。

**5. 工程と音声を保存し、必要なところから再開する**

最初は単一ワーカーとファイルロック、原子的なJSON保存で実装します。CLIは同期実行を基本とし、中断後の`resume`を保証します。バックグラウンド常駐や多重ワーカーは、必要になった段階で追加します。

工程は`analyzed → needs_decision → planned → rendering → checking → needs_revision → assembled → exported → verified`を基本とし、`failed`・`cancelled`・`needs_recovery`を別に持ちます。工程名だけで再開せず、完了したファイルのハッシュと検査結果を照合します。途中の音声ファイルを完成品として再利用しません。

キャッシュには、読み上げ用テキスト、話者、エンジン版、実際に使用したボイス資産の識別情報、速度・ピッチ・感情、辞書スナップショット、分割仕様を含めます。初期版は辞書全体のハッシュで無効化して正しさを優先します。辞書が変わった場合、旧辞書で作った音声を混ぜて最終化しません。

保存内容は原稿、読み補正、辞書差分、区間ごとの音声と履歴、QA、スライド時間、最終成果物です。語彙や原稿を含む作業領域はローカルに置き、Git管理から除外します。原稿をホスト側AIに渡す範囲は明示します。合成・ASRがローカルでも、ホストがクラウドAIであれば判断用テキストはそのホストで処理されます。

**6. 静止スライド動画を先に完成させる**

PowerPointによる描画を基本候補とします。原本を変更せず、作業コピーから画像またはPDFを生成します。実装開始時に、現在のMac版PowerPointで許可された自動化経路と、終了・ファイル出力を検出できる方法を確認します。描画できたことをファイルの存在だけで判定せず、実際のスライドと照合します。

画像と検証済み音声からFFmpegでMP4を作ります。スライドの表示時間は、先頭余白＋音声実測長＋末尾余白です。休止は「追加する無音」と「最終的な無音の目標値」を別の設定にします。初期版では元の音声サンプルを保持して追加する方式を使い、息や子音を削る無音除去は自動適用しません。

サンプル数を基準に音声の時間を管理し、映像フレームの丸めを記録します。最終MP4の映像と音声の差は1フレーム以内を初期受入基準とし、各スライド境界も確認します。音量調整後の音声を再検査します。

アニメーション、動画、段階表示を忠実に維持する経路は別の機能です。単純に静止画へ落として「再現できた」と報告しません。Mac版PowerPointの埋め込み音声・動画書き出しには制約の説明があるため、PPTXに音声を埋めて動画出力する経路も独立した検証対象です。[Microsoftの動画出力説明](https://support.microsoft.com/en-us/powerpoint/save-a-presentation-as-a-movie-file-or-mp4-in-powerpoint-for-mac)

**7. CLIとSkillの契約を先に固定する**

CLIの予定形は次のとおりです。画面用の説明と、エージェント向けJSONを分けます。

| コマンド案 | 役割 |
|---|---|
| `vp-manager doctor --json` | バージョン、話者、実行可能性、GUI競合、依存ツールを確認 |
| `vp-manager analyze INPUT --job DIR --json` | 原稿抽出、用語候補、スライド一覧、対応できない要素を保存 |
| `vp-manager apply-decisions JOB --file decisions.json` | AIの読み・品詞・分割候補を検証して適用 |
| `vp-manager render JOB` | 辞書処理と区間ごとの音声生成 |
| `vp-manager verify JOB --json` | 内容・音響検査と修正候補の根拠を出力 |
| `vp-manager assemble JOB` | 段落・スライド音声の結合 |
| `vp-manager export-video JOB` | 描画結果と音声から動画を作成 |
| `vp-manager resume JOB` / `status JOB --json` | 再開可能な工程を選び、状態と必要な判断を返す |

共通の返却項目は`schema_version`、`job_id`、`status`、`artifacts`、`issues`、`next_action`です。AIによる変更には`source_revision`と元の対象文字列を含め、古い原稿への判断を拒否します。終了コードで入力不備・環境不備・要判断・合成失敗を区別し、単なるプロセス成功と品質合格を分けます。

Skillは`.agents/skills/voicepeak-production/SKILL.md`としてプロジェクト内に置く予定です。入力と目的を確認し、`doctor`、解析、判断JSON、生成、検証、局所修正、出力確認の順に案内します。辞書ファイルの直接編集、任意の音声加工コードの都度生成、QAの未解決項目を隠すことを避ける指示を含めます。コードの所有者はPythonパッケージで、Skill内へ処理を複製しません。

Pythonはまず3.12を基準に独立した`pyproject.toml`とロックファイルを用意します。中核は`cli`、`jobs`、`text`、`lexicon`、`voicepeak`、`qa`、`pptx`、`video`に分けます。NumPy・soundfile・mlx-whisperとFFmpegを候補とし、ASRは追加依存に分離します。具体的な版は実装時に互換性を確認して固定します。

voice-modelからは読み補正、ASR、音響計測、ノート保全、音声結合の考え方と検証データを再利用します。ただし、28枚・162段落の固定値、既存の出力パス、import時に引数処理するスクリプトはそのまま製品の依存にしません。

**8. 実装は受入条件を満たした段階で進める**

| 段階 | 実装内容 | 完了条件 |
|---|---|---|
| M1：実行基盤 | Pythonパッケージ、CLI、doctor、ジョブ保存、VOICEPEAKアダプター、分割 | テキストとファイルからWAV。140文字超過・不正話者を事前拒否。中断後の再開で欠落・重複がない |
| M2：辞書と読み | 候補JSON、読み補正、品詞・アクセント、辞書の退避・差分・復元・確定追加 | 架空語の反映と取り消し、既存語の保全、競合時停止、強制終了後の回復を試験。記号付き原文を壊さず合成できる |
| M3：QAとSkill | ローカルASR、音響検査、修正候補比較、上限、Skill | 良い例と誤読例を含む評価セットで採用判定を確認。要判断を自動合格にしない。Skillの実依頼からCLIを通してWAVを作る |
| M4：PPTXとMP4 | ノート・非表示・空原稿・描画の扱い、スライド時間、動画合成 | 小規模PPTXで原本のハッシュ保持、ノート対応、画面照合、音声同期を確認。その後に代表的な実資料を全ページ検証 |
| M5：継続利用 | README、設定、回帰試験、再開・辞書回復手順、導入用Skill | 同じ依頼の再実行、原稿変更、辞書変更、依存更新で正しく再生成。保留理由と成果物へ利用者が到達できる |

M1〜M3で音声制作を完成させ、M4で動画化します。MCPは、これらの操作を公開する薄い窓口として追加できます。将来ホストから独立した無人運転が必要になった場合は、同じ判断JSONの契約をAI APIアダプターに実装します。
